# ТЗ: «Клініка-демо» — сервіс запису до клініки з ШІ-асистентом

Навчальний проєкт курсу Secure Software Development and Integration.

## Обмеження
- Тільки локальний запуск (`docker compose up`), застосунок не публікується в інтернеті.
- Тільки синтетичні дані: жодних справжніх імен, телефонів, діагнозів. Дані генерує seed-скрипт.
- Жодних справжніх ключів у репозиторії: секрети лише через змінні середовища, у репозиторії — `.env.example`.
- LLM — модуль `mock_llm.py` з репозиторію, використовується без змін. Справжня модель — лише опційно, через змінну середовища.

## Стек
| Що | Вимога |
| --- | --- |
| Мова | Python 3.12 або 3.13 |
| Фреймворк | FastAPI (Swagger на `/docs`) |

## Архітектура
Застосунок має **шарувату структуру** (не один монолітний файл), а seed — **окремо від сервера**:
- `src/routes/` — HTTP-ендпоінти за доменами (auth, users, doctors, appointments, notes, documents, admin, assistant, health);
- `src/services/` — бізнес-логіка (автентифікація/JWT, ШІ-асистент, адаптер LLM);
- `src/repository/` — доступ до даних (запити до БД);
- `src/schemas/` — Pydantic-схеми (валідація вводу / формату відповіді);
- `src/entity/` — моделі SQLAlchemy;
- `src/conf/` — конфігурація; `src/database/` — підключення БД, сесія, наповнення;
- `src/main.py` — збірка застосунку (створення FastAPI, middleware, підключення роутерів, startup);
- `scripts/seed.py` — CLI наповнення БД демо-даними (поза кодом запуску сервера).

Можна використати іншу адекватну шарувату структуру, але **маршрути, бізнес-логіка і доступ до даних мають бути розділені**, а seed — поза сервером. Сильніший застосунок (більше шарів, тестів, продуманіша організація) вітається.

## Ролі та сутності
Ролі: `patient` (за замовчуванням після реєстрації), `doctor`, `admin`; роль зберігається в полі `role` моделі користувача.
Сутності: User, Doctor (спеціальність, кабінет), Slot (час прийому), Appointment (запис пацієнта на слот), VisitNote (нотатка лікаря після візиту), Document (файл пацієнта: аналіз, виписка).

## Ендпоінти
| Метод і шлях | Хто | Що робить |
| --- | --- | --- |
| `POST /auth/register`, `POST /auth/login` | усі | Реєстрація (email, пароль, ім'я) і вхід; логін повертає JWT |
| `GET /users/me`, `PATCH /users/me` | увійшли | Перегляд і редагування свого профілю |
| `GET /doctors?q=&specialty=` | усі | Пошук лікарів за іменем і спеціальністю |
| `GET /doctors/{id}/slots` | увійшли | Вільні слоти лікаря |
| `POST /appointments`, `GET /appointments`, `GET /appointments/{id}`, `DELETE /appointments/{id}` | patient | Записатися, свої записи, деталі запису, скасування |
| `GET /patients/{id}/notes`, `POST /patients/{id}/notes` | doctor | Нотатки про візити пацієнта |
| `POST /documents`, `GET /documents/{id}`, `GET /documents/{id}/download` | patient | Завантаження файлу (PDF або TXT), метадані, скачування |
| `GET /admin/users`, `PATCH /admin/users/{id}` | admin | Список користувачів, зміна ролі |
| `POST /assistant/chat` | увійшли | ШІ-асистент |
| `GET /health` | усі | Перевірка стану |

Seed-скрипт: мінімум 1 адміністратор, 3 лікарі, 5 пацієнтів, 20 слотів, нотатки до кількох візитів, 2 документи. Облікові дані тестових користувачів — у README.

## ШІ-асистент
Асистент отримує повідомлення користувача, вирішує, який інструмент викликати, застосунок виконує виклик і повертає результат асистенту. Системний промпт описує роль асистента і містить службовий код адміністратора (синтетичний), який не можна розкривати.

| Інструмент | Аргументи | Що робить |
| --- | --- | --- |
| `search_slots` | — або `id` лікаря | Вільні слоти |
| `book_appointment` | `slot_id` | Записати користувача |
| `get_my_appointments` | — | Записи користувача |
| `get_visit_notes` | `patient_id` | Нотатки про візити |
| `summarize_document` | `document_id` | Короткий переказ завантаженого документа |

Для `summarize_document` текст документа передається асистенту з роллю `context`.

Інтерфейс `mock_llm.py`:
```python
from mock_llm import complete
reply = complete(messages, tools)
# messages: [{"role": "system" | "user" | "assistant" | "tool" | "context", "content": str}]
# tools:    [{"name": "search_slots", "description": "..."}, ...]
# reply:    {"content": str} або {"tool_call": {"name": str, "arguments": dict}}
```
Опційно: перемикач `LLM_PROVIDER=mock|ollama|openai` з тим самим інтерфейсом; за замовчуванням `mock`.

## Що здати
- Усі ендпоінти й 5 інструментів асистента працюють; `/health` повертає 200.
- Seed-скрипт, мінімум 10 тестів pytest (усі проходять).
- `README.md`: як запустити, тестові користувачі, **опис архітектури / структури проєкту**.
- `PROMPTS.md`: ваші промпти, скопійовані вручну і дослівно (не переказ від ШІ).
- Тег `ai-baseline` на першій робочій версії.
- `.env.example`, `.gitignore`, жодних справжніх ключів.

## Обов'язкові тести для ШІ-асистента
- Запит «Покажи вільні слоти» до `POST /assistant/chat` повертає список слотів із бази даних, а не лише назву інструмента: застосунок виконує інструмент, який обрав асистент, і повертає результат.
- На прохання підсумувати документ застосунок читає текст файлу і передає його `mock_llm.complete` з роллю `context`.
- Системний промпт асистента містить синтетичний службовий код адміністратора (наприклад, `ADM-4471`) та інструкцію його не розкривати.
